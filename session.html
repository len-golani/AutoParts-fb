What We Built So Far

Phase 1 — VIN Decoder + Vehicle Lookup ✅ Complete

  • React 19 + TypeScript + Vite frontend with React Router 7
  • VIN decoder calling NHTSA vPIC API directly from the browser — no backend needed
  • Manual Make/Model/Year selector using NHTSA API directly
  • Vehicle catalog pages: Home, VIN Decoder, Catalog, Brand
  • Reusable components: Layout, VehicleCard, VINScanner
  • Catalog data served from local JSON seed files (imported into frontend)
  • Admin dashboard (readme.html) for tracking APIs and credentials
  • Project roadmap with 7 phases documented in dashboard
  • Frontend flattened to repository root for Freebuff hosting
  • Preview running on Freebuff Cloud — fully functional VIN decoding

Key Decisions Made

  • Private/proprietary — not open-source.
  • Direct NHTSA calls from browser — NHTSA supports CORS (access-control-allow-origin: *), so no backend proxy needed for VIN decoding
  • Local catalog data — brands and popular models imported as JSON modules in the frontend
  • No dummy features — every visible feature is functional
  • Local-first strategy — Phase 3 uses pre-rendered PNG/SVG, Phase 4 uses client-side Three.js
  • Supabase for database — PostgreSQL, Auth, and Storage on free tier

Database Plan (Phase 2)

Supabase PostgreSQL Schema

brands
├── id (uuid, PK)
├── name (text)
├── logo_url (text)
└── created_at (timestamp)

vehicles
├── id (uuid, PK)
├── brand_id (uuid, FK → brands)
├── model (text)
├── year_start (int)
├── year_end (int)
└── image_url (text)

part_groups
├── id (uuid, PK)
├── vehicle_id (uuid, FK → vehicles)
├── name (text)          -- e.g. "Engine", "Brakes", "Body"
├── diagram_url (text)   -- PNG/SVG path (Phase 3)
└── sort_order (int)

parts
├── id (uuid, PK)
├── part_group_id (uuid, FK → part_groups)
├── part_number (text)
├── name (text)
├── description (text)
├── price (decimal)
├── image_url (text)
├── model_3d_url (text)  -- GLB/glTF path (Phase 4)
└── compatibility_notes (text)

vehicle_part_fitments
├── id (uuid, PK)
├── vehicle_id (uuid, FK → vehicles)
├── part_id (uuid, FK → parts)
├── oem_number (text)
├── is_compatible (boolean)
└── notes (text)

user_events (analytics)
├── id (uuid, PK)
├── event_type (text)     -- 'page_view', 'vin_search', 'part_click'
├── page (text)
├── metadata (jsonb)
├── session_id (text)
├── user_id (uuid, nullable FK → auth.users)
├── created_at (timestamp)

Local Development Setup

💡 GitHub Desktop: You have both AutoParts and CarPartsFinder cloned. Use "Open in Visual Studio Code" from GitHub Desktop to edit locally. Changes sync via push/pull without opening a browser.

Start the Frontend Locally

# Frontend only (VIN decoder works without backend!)
cd AutoParts
npm install
npm run dev

# Open http://localhost:5173
# VIN Decoder works immediately — calls NHTSA directly from browser

Start the Backend (Optional — for Phase 2+)

# Terminal 1 — Backend (only needed for Phase 2+ catalog API)
cd backend
pip install -r requirements.txt
python -m uvicorn app.main:app --reload --port 8000

# Or use START.ps1 on Windows
.\START.ps1

GitHub Desktop Workflow (No Browser Needed)

  • Open GitHub Desktop → select AutoParts
  • Click Open in Visual Studio Code to edit files locally
  • After editing, return to GitHub Desktop → review changes → Commit to main → Push origin
  • Freebuff auto-syncs when you push to GitHub
